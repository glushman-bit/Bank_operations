# Аналитический сервис банковских операций

![Python](https://img.shields.io/badge/Python-3.x-blue)
![Tests](https://img.shields.io/badge/tests-passing-brightgreen)
![Coverage](https://img.shields.io/badge/coverage-100%25-brightgreen)

Приложение для анализа банковских операций на основе данных из Excel-файла.
Проект собирает основную информацию по операциям, формирует аналитические отчёты, позволяет искать транзакции по номеру телефона, анализировать кэшбэк, а также получать актуальные курсы валют и стоимость акций через внешние API.

## Возможности

Приложение предоставляет несколько групп функций.

### Основная информация

При запуске формируется итоговая информация:

* приветствие в зависимости от времени суток;
* список банковских карт и сумма расходов по каждой карте;
* расчёт кэшбэка;
* пять крупнейших расходов;
* курсы выбранных валют;
* стоимость выбранных акций.

Результат формируется в формате JSON.

### Поиск транзакций

Пользователь может выполнить поиск операций по номеру телефона.

Перед поиском номер нормализуется: из него удаляются пробелы, скобки, дефисы и другие символы, не являющиеся цифрами.

Например:

```text
+7 (999) 123-45-67
```

преобразуется в:

```text
79991234567
```

Это позволяет искать номер независимо от его исходного формата.

### Анализ расходов

Можно получить сумму расходов по определённой категории за последние три месяца относительно указанной даты.

Если пользователь не указывает дату, используется текущая дата.

### Анализ кэшбэка

Приложение позволяет получить информацию о кэшбэке по категориям за выбранный год и месяц.

Учитываются операции:

* за указанный период;
* с положительным значением кэшбэка;
* с отрицательной суммой платежа.

Если подходящих операций нет, пользователь получает соответствующее сообщение, а в журнал записывается предупреждение.

### Курсы валют

Для получения актуальных курсов используется внешний API.

Список валют задаётся в пользовательских настройках.

### Стоимость акций

Для получения стоимости акций используется API Twelve Data.

Список интересующих пользователя акций задаётся в `user_settings.json`.

### Назначение модулей

#### `views.py`

Содержит основную функцию формирования итоговой информации:

```
main_info()
```

Функция объединяет результаты различных аналитических функций и формирует итоговый JSON.

---

#### `utils.py`

Содержит основные вспомогательные функции:

* `get_time_for_greeting()` — приветствие;
* `get_list_cards()` — анализ расходов по банковским картам;
* `top_transactions()` — получение топ-5 операций;
* `get_curs_currency()` — получение курсов валют;
* `stock_prices()` — получение стоимости акций.

---

#### `services.py`

Содержит функции для дополнительного анализа:

* `normalize_phone()` — нормализация номера телефона;
* `find_transactions_by_phone()` — поиск операций по номеру телефона;
* `cashback_analysis()` — анализ кэшбэка по категориям.

---

#### `reports.py`

Содержит функции формирования отчётов.

Основная функция:

```
spending_by_category()
```

Она рассчитывает расходы по выбранной категории за последние три месяца.

---

#### `decorators.py`

Содержит:

* настройку логирования;
* глобальный объект `logger`;
* декоратор `@log()`.

Декоратор фиксирует успешный запуск функции и записывает информацию об исключениях вместе с traceback.

## Входные данные

Основные банковские операции хранятся в файле:

```
data/operations.xlsx
```

Файл загружается с помощью Pandas:

```
df = pd.read_excel("data/operations.xlsx")
```

Для работы аналитических функций используются столбцы с информацией об операциях.

В зависимости от функции используются такие поля, как:

```
Дата операции
Дата платежа
Сумма платежа
Номер карты
Категория
Описание
Кэшбэк
```

### Важно

Названия столбцов в Excel должны точно соответствовать названиям, используемым в коде.

Например:

```
df["Сумма платежа"]
```

и:

```
df["Категория"]
```

При изменении названия столбца соответствующий код также необходимо изменить.

## Работа программы

После запуска приложение формирует основную информацию.

Пользователь получает:

```text
greeting
cards
top_transaction
currency_rates
stock_prices
```

После этого приложение предлагает дополнительные операции.

### Поиск по номеру телефона

Пользователь получает запрос:

```text
Проверить транзакции по номеру телефона? да/нет
```

При выборе `да` необходимо ввести номер телефона или его часть.

Например:

```text
Введите номер телефона или первые цифры: 79991234567
```

Результатом будет список найденных транзакций.

---

### Отчёт по категории

Следующий запрос:

```text
Проверить транзакции по категории за 3 месяца? да/нет
```

При положительном ответе необходимо указать категорию и дату окончания периода.

Например:

```text
Введите категорию: Продукты
Введите дату конца периода в формате, по умолчанию дата-сегодня: гггг.мм.дд:
```

Дата вводится в формате:

```text
2026.08.23
```

Если дата не указана, используется текущая дата.

---

### Анализ кэшбэка

Последний дополнительный запрос:

```text
Проверить выгодные категории повышенного кешбэка за месяц? да/нет
```

При выборе `да` вводятся год и месяц:

```text
Введите год в формате: гггг - 2026
Введите месяц в формате: мм - 8
```

После этого приложение анализирует операции за указанный период.

Если данные отсутствуют:

```text
По вашему запросу ничего не найдено.
```

## Логирование

Для логирования используется стандартный модуль Python:

```python
import logging
```

Логгер создаётся с именем:

```text
app
```

Логи сохраняются в:

```text
logs/mylog.txt
```

Также сообщения могут выводиться в консоль.

Используемый формат:

```text
дата и время - функция - имя логгера - уровень - сообщение
```

Пример:

```text
2026-08-23 18:30:15 - main_info - app - INFO: - Успешный запуск функции: main_info
```

### Уровни логирования

В проекте используются:

* `INFO` — успешное выполнение функций и информационные сообщения;
* `WARNING` — отсутствие данных или некорректный пользовательский запрос;
* `ERROR` / `EXCEPTION` — ошибки выполнения.

---

## Декоратор логирования

Для автоматического логирования функций используется декоратор:

```python
@log()
```

При успешном выполнении функция записывает информацию в лог.

Если возникает исключение:

```python
except Exception:
    logger.exception(...)
    raise
```

в лог попадает информация об ошибке и traceback, после чего исключение передаётся дальше.

Это позволяет не дублировать одинаковый код логирования в каждой функции.

## Обработка ошибок

Приложение учитывает несколько типов проблем.

### Некорректная дата

Если пользователь вводит дату в неправильном формате, используется текущая дата.

Ожидаемый формат:

```text
ГГГГ.ММ.ДД
```

Например:

```text
2026.08.23
```

### Отсутствие данных

При отсутствии подходящих транзакций функции возвращают сообщение:

```text
По вашему запросу ничего не найдено.
```

или формируют отчёт с нулевой суммой.

### Ошибки API

При недоступности внешнего API приложение должно зафиксировать проблему в журнале и вернуть безопасный результат вместо необработанного исключения.

Для сетевых запросов рекомендуется использовать `timeout` и обработку:

```python
requests.RequestException
```

## Возможные улучшения

Проект уже разделён на логические модули, однако его можно развивать дальше.

### Автоматические тесты

Добавить `pytest` и покрыть тестами:

* расчёт расходов;
* анализ карт;
* поиск по телефону;
* расчёт кэшбэка;
* формирование отчётов;
* обработку пустых DataFrame.

### Улучшение обработки API

Для HTTP-запросов можно добавить:

```python
timeout
```

и обработку:

```python
requests.RequestException
```

Также полезно проверять структуру JSON, полученного от API.

### Валидация пользовательского ввода

Можно вынести ввод года, месяца, даты и ответа `да/нет` в отдельные функции.

Это позволит повторно использовать одинаковую логику и избежать падения программы при вводе некорректных значений.

### Конфигурация путей

Пути к файлам можно вынести в настройки, чтобы приложение не зависело от текущей рабочей директории.

### Типизация

Можно более точно указать типы возвращаемых значений.

Например вместо:

```python
def cashback_analysis(...) -> Dict[str, float]:
```

если функция фактически возвращает JSON-строку:

```python
def cashback_analysis(...) -> str:
```

Либо, что ещё удобнее для тестирования, возвращать Python-словарь из функции, а сериализацию выполнять только на уровне интерфейса приложения.
